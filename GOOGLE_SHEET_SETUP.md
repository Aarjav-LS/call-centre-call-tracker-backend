# Connecting reports to a shared Excel sheet

Operators click **Send report to supervisor**. The API forwards that payload to a Google Sheet that
the supervisor owns. The bridge is a small Google Apps Script web app, so no Google credentials or
service-account keys ever live in the repository or on Render.

## 1. Create the sheet

1. Go to [sheets.new](https://sheets.new) and name it, for example `CallTrack Reports`.
2. Create two tabs. The script creates the headers if they are missing, but naming them up front
   makes the setup obvious:
   - `Call Summary` — one row per report
   - `Clusters` — one row per cluster

## 2. Add the Apps Script

1. In the sheet, open **Extensions > Apps Script**.
2. Delete the placeholder code and paste:

```javascript
const SUMMARY_TAB = 'Call Summary'
const CLUSTERS_TAB = 'Clusters'

const COUNTER_KEYS = [
  'courseNA', 'feesHesitation', 'discussParents', 'needsFollowUp',
  'confirmedVisits', 'notInterested', 'alreadyVisited', 'alreadyAdmitted',
  'hungUp', 'wrongNumber', 'notReceived',
]

function doPost(e) {
  const payload = JSON.parse(e.postData.contents)
  appendSummary(payload)
  appendClusters(payload)
  return ContentService.createTextOutput(JSON.stringify({ ok: true }))
    .setMimeType(ContentService.MimeType.JSON)
}

function setup() {
  const summary = SpreadsheetApp.getActive().getSheetByName(SUMMARY_TAB)
  if (summary.getLastRow() === 0) {
    summary.appendRow([
      'Report date', 'Report time', 'Operator', ...COUNTER_KEYS,
      'Total received', 'Total not received', 'Total calls', 'Coverage %',
    ])
  }
  const clusters = SpreadsheetApp.getActive().getSheetByName(CLUSTERS_TAB)
  if (clusters.getLastRow() === 0) {
    clusters.appendRow(['Report date', 'Report time', 'Operator', 'Cluster code', 'College name'])
  }
}

function appendSummary(payload) {
  const sheet = SpreadsheetApp.getActive().getSheetByName(SUMMARY_TAB)
  const d = payload.derived
  sheet.appendRow([
    payload.reportDate,
    payload.reportTime,
    payload.operator,
    ...COUNTER_KEYS.map((k) => payload.state[k]),
    d.totalReceived,
    d.totalNotReceived,
    d.totalCalls,
    d.coverage,
  ])
}

function appendClusters(payload) {
  if (!payload.clusters || payload.clusters.length === 0) return
  const sheet = SpreadsheetApp.getActive().getSheetByName(CLUSTERS_TAB)
  const rows = payload.clusters.map((c) => [
    payload.reportDate,
    payload.reportTime,
    payload.operator,
    c.code,
    c.college,
  ])
  sheet.getRange(sheet.getLastRow() + 1, 1, rows.length, 5).setValues(rows)
}
```

The date and time are generated by the CallTrack server, not by each operator's computer, so a
laptop with a wrong clock or the wrong timezone cannot corrupt the record. The split into two columns
also means the supervisor can sort by date, group by day, or filter a single day without parsing a
timestamp.

3. Run `setup` once from the editor toolbar and approve the permission prompt. This writes the header
   rows.
4. Choose **Deploy > New deployment**, type **Web app**, and set **Execute as** to *Me* and **Who has
   access** to *Anyone*. Click Deploy and copy the **Web app URL**.

## 3. Point the API at it

In Render, open the CallTrack service, go to **Environment**, and set:

```
REPORT_WEBHOOK_URL = https://script.google.com/macros/s/AKfycb...../exec
REPORT_TIMEZONE    = Asia/Kolkata
```

Save and the service restarts. Confirm it is live:

```bash
curl https://your-api.onrender.com/health
# {"status":"ok","uptime":12.3,"sheetConfigured":true}
```

`sheetConfigured: true` means reports will reach the sheet.

### About `REPORT_TIMEZONE`

This one is worth setting. Render's servers run in UTC, so without it the date and time columns would
record UTC rather than the moment the operator actually submitted. Set it to your own timezone
(`Asia/Kolkata`, `Europe/London`, `America/New_York`, and so on) and every row is stamped in the
time the desk actually works in. It falls back to `UTC` if you never set it.

## Notes

- The Apps Script URL is a secret in practice. Anyone holding it can append rows, so do not publish
  it. Render keeps it in environment variables, not in the repo.
- Rows append in the order reports arrive, which is not a guaranteed sort by date. To tidy the sheet,
  select the `Report date` column, then **Data → Sort by column A**. Re-running `setup` is safe: it
  only writes headers when a tab is empty, so it will not overwrite collected data.
- Google Apps Script web apps can take several seconds to respond on a cold start. The API already
  tolerates slow sheets; if a push fails, the report is written to `data/reports.csv` instead and the
  operator is told it went to the server log rather than the sheet.
- If a report ever goes missing from the sheet, check the `reports.csv` and `reports-clusters.csv`
  files. On Render's free tier those live on an ephemeral disk, so attach a persistent disk if you
  need the fallback to be durable.
